# SPHEREx Blink

Сайт для задания NASA Space Apps: вводите координаты участка неба и смотрите, как он меняется между проходами телескопа SPHEREx. Все изображения настоящие, из архива NASA/IPAC IRSA.

## Открыть и запустить в VS Code

1. VS Code → File → Open Folder → `Projects/spherex-blink`.
2. Откройте терминал VS Code (Terminal → New Terminal) и выполните `python3 server.py`.
3. Откройте http://localhost:8765.

Устанавливать ничего не нужно.

## Опубликовать, чтобы ссылка открывалась у всех (Vercel, бесплатно)

1. Загрузите папку в репозиторий на GitHub.
2. На vercel.com: Add New → Project → выберите репозиторий → Deploy. Настройки не меняйте.
3. Получите адрес вида `spherex-blink.vercel.app`.

На Vercel работает всё, включая ввод любых координат: файл `api/irsa.js` пересылает запросы в архив NASA, `vercel.json` подключает его по адресу `/irsa/...`. Эту часть мы не проверяли на самом Vercel, проверьте после публикации на любой новой точке неба.

Без сервера (GitHub Pages, любой статический хостинг) работают история, результаты и пять сохранённых целей, но не произвольные координаты.

## Файлы

| Файл | Что делает |
|---|---|
| `index.html` | Разметка страницы |

| `app.js` | Анимация при прокрутке, карточки результатов, инструмент |

## Возможности

- Ввод координат (градусы или часы/градусы), пять готовых целей из задания, координаты в ссылке и режим встраивания (`&embed=1`).
- Просмотр проходов телескопа как видео, отдельно по каждому из шести детекторов или по всем сразу; режимы мигания, разности и суммы.
- Клик по объекту: сдвиг в ″/год, спектр по всем снимкам (0,75–5 мкм), график яркости по проходам.
- **Автопоиск движущихся объектов**: сравнение положений всех источников поля, оценка шума, проверка на других детекторах и сверка с Gaia DR3.
- Каталоги Gaia DR3 (с учётом собственного движения на дату снимка) и AllWISE поверх снимка; ссылка на участок в Aladin.
- Свои метки: обвести объект, подписать, получить координаты.
- Флаги качества пикселей, версия релиза и даты снимков.
- Гид для новичков: пошаговые подсказки при первом входе и по кнопке.

## Как устроена обработка

1. Запрос к IRSA (TAP): какие снимки SPHEREx накрывают точку. Сейчас это 200–350 снимков на точку.
2. Для каждого снимка скачивается вырезка. Файл читается потоком и обрывается после нужных слоёв: таблица PSF занимает 97% файла и не нужна.
3. Из IMAGE вычитается ZODI (модель зодиакального фона), плохие пиксели по FLAGS исключаются.
4. Кадры совмещаются по WCS из заголовка (TAN-SIP) на сетке «север вверху» с шагом 3,075″.
5. Кадры одного детектора за один проход складываются медианой. Проход — группа снимков без разрыва больше 60 дней и не длиннее 75 дней.
6. Сдвиг: центр объекта находится в каждом проходе, скорость = расстояние между первым и последним проходом / время.
7. Спектр: апертурная фотометрия на каждом снимке; длина волны берётся из таблицы WCS-WAVE для того места детектора, куда попал объект.

## Обновление данных

SPHEREx публикует новые снимки каждую неделю. Произвольные координаты всегда запрашиваются из архива заново. Чтобы пересобрать пять сохранённых целей, откройте http://localhost:8765/?build=1 при запущенном `server.py` (около часа).

## Честные ограничения

- Пиксель SPHEREx 6,15″, проходы раз в полгода: сдвиг меньше примерно 1″ не измерить.
- Кадр детектора — медиана снимков на разных длинах волн внутри его диапазона.
- Спектр без апертурных поправок и без учёта соседних звёзд: для просмотра, не для публикации.
- У очень ярких звёзд ядро насыщено; такие точки и кадры помечены.
